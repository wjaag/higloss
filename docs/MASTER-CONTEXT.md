## Design direction

Keep as brand inputs:

- existing HI-GLOSS DESIGN logo;
- existing photography and project imagery;
- existing blue / dark visual language;
- existing brand facts and real project evidence.

Replace or refactor:

- information architecture where it improves search intent;
- visual hierarchy, spacing, typography scale, cards, navigation and conversion paths;
- duplicated or brittle CSS/JS;
- SEO implementation that duplicates plugin responsibilities;
- image metadata and accessibility gaps;
- unnecessary WordPress asset loading.

## SEO ownership rule

### WordPress/theme owns

- semantic HTML and heading hierarchy;
- crawlable internal links;
- canonical-friendly URLs generated by WordPress;
- image `alt`, dimensions, loading and fetch priority;
- clean archive/CPT templates;
- breadcrumbs only if implemented as presentation/navigation, not competing metadata;
- performance and accessibility;
- content structure and internal linking.

### Yoast SEO owns

- title tags;
- meta descriptions;
- canonical URLs;
- XML sitemaps;
- robots directives;
- Open Graph / social metadata;
- Schema graph where Yoast is active.

The theme must not print competing `<title>`, canonical, robots, OG or duplicate JSON-LD. Do not remove or replace Yoast-generated metadata from theme code unless a documented, tested integration requires it.

## Content principles

- Write for real customer intent first; do not keyword-stuff.
- Prefer Polish natural-language queries such as `oklejanie samochodów Szczecin`, `zmiana koloru auta`, `PPF Szczecin`, `reklama na samochodach Szczecin`, `przyciemnianie szyb Szczecin` where genuinely relevant.
- Every important service gets one primary landing page and supporting portfolio/guide content.
- Use descriptive anchor text instead of generic `kliknij tutaj`.
- Keep claims tied to evidence available to the business.
- Preserve existing valuable URLs whenever possible. Any intentional URL change requires a 301 migration entry.

## UX principles

- One primary CTA: free project quote.
- Secondary CTA: call the studio.
- Service pages answer: what, for whom, process, materials, duration, warranty, examples, FAQ, next step.
- Portfolio entries answer: vehicle, goal, material, finish, scope, time, result.
- Mobile is a first-class layout, not a collapsed desktop layout.
- Motion is progressive enhancement and respects `prefers-reduced-motion`.

## Engineering principles

- WordPress APIs and escaping everywhere.
- No business logic in large template files when it can live in `inc/`.
- No plugin-specific hacks without a documented reason.
- No hard-coded content when the WordPress content model already provides it.
- Use `wp_enqueue_*` for assets.
- Use `filemtime()` cache busting only where appropriate.
- Avoid global CSS resets that can break plugin/admin/front-end components.
- Keep PHP templates semantic and component-oriented.

## Definition of done

A change is not done until:

1. PHP syntax is valid.
2. Desktop and mobile layouts are checked.
3. No visible console errors are introduced.
4. No Yoast responsibility is duplicated.
5. Internal links remain crawlable.
6. Images have deliberate `alt` text or an intentionally empty alt for decorative images.
7. Width/height are supplied for content images where known.
8. Core Web Vitals impact is considered.
9. Existing URLs are preserved or a redirect is documented.
10. The change is described in the relevant docs/PR.
